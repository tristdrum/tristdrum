# Airbnb browser pilot

Read-only, fail-closed host-website evidence code for Bougainvillea, Spekboom and Jasmine. **Not a viable live source yet.** No cloud deployment/login, Airbnb write, guest message, or real guest fixture was made for this branch.

## Observed UI and limits

Read-only inspection of the existing signed-in personal browser on 2026-09-24 established the `.co.za` host routes and DOM shape, without copying cookies or guest content to the repo or cloud:

- Calendars use `https://www.airbnb.co.za/multicalendar/<listingId>`. Three simultaneous `div[role="grid"][aria-label="Month YYYY"]` grids contain `button[data-date]` inside day cells. `div[data-testid="reservation-bar"]` is inside a clickable row, not an anchor. A bar opens `/multicalendar/<listingId>/reservation/<code>`, with a labelled confirmation code, `guestFirstName`, and a visible `/users/profile/<id>` guest link.
- The parser requires each grid's full month and the current SAST month. A day may describe two adjacent bookings; all `Checkin on ..., checkout on ...` intervals are collected and overlapping/malformed pairs fail. A labeled bar must have a recognized selector and parseable interval. An empty decorative bar is ignored **only** when a nonempty bar has the exact same selector; an unmatched empty bar fails. Labeled-bar intervals must exactly match the distinct intervals described by reserved days, and **every** labeled bar (up to 80 per listing) must yield the same complete detail for its interval, with route/visible-code agreement. Unknown, extra, missing or conflicting bars fail the snapshot. `guestProfileId` comes only from one visible numeric guest-profile link; missing or ambiguous links yield `null`. No identity is inferred from a display name.
- Reservation details now require a visible sidebar lifecycle heading tied to that code (such as `Past guests`, `Upcoming guests`, `Pending request`, or `Cancelled`) and an explicit `group of N` total reconciled against the Guests section's adult, child and infant labels. The snapshot exposes `status`, `guestCount` and `guestComposition: {adults, children, infants}`. A missing heading, missing count, or mismatched sum fails closed. A heading like `Upcoming guests` is **not** treated as canonical confirmed status or permission to approve a request. One sampled older reservation showed a group total and Guests breakdown that did not reconcile; the strict parser would refuse it. No canonical booking write is made by this pilot.
- Messages use `/hosting/messages`, with visible conversation IDs in `inbox_list_<id>` markers. Read-only local inspection found 15 visible rows, while the header showed 58 unread (not a total-thread count); `#list_inbox` is not scrollable, but an ancestor is. Every visible row must identify exactly one thread. Traversal advances the scrollable ancestor in overlapping steps and fails if it cannot reach a stable end. The selected thread uses `message-thread-container`, `message-list`, `MessageOuterRegistryWrapperSpacingProps`, and `html-rich-text-container`, with no `article` or `data-message-id` contract. Its extractor deliberately fails closed, so Messages and overall readiness remain false until stable sender, timestamp, ID and entire-history evidence are established. Opening Messages auto-selected a thread and may mark it read; no claim of zero observable side effects is made.
- The observed Jasmine reload made 159 GET and four first-party POST requests. This pilot still blocks non-GET/HEAD/OPTIONS. For an allowed request it fetches one hop with Playwright `maxRedirects: 0` and **rejects every 3xx response before the browser sees it**. A browser-level synthetic test found that Chromium can follow a fulfilled redirect without a second route callback; refusing all redirects closes that gap, including cross-host and HTTP downgrades. This may prevent the site from rendering. **Whether the signed-in cloud calendar renders with POST and redirects blocked is unproven.** Do not relax either boundary without a separate write-risk review and browser-level proof.

All app tests use synthetic guest names, booking codes, profile IDs and page fixtures. A signed-in cloud end-to-end run and real UI read-receipt assessment remain blockers. No local Chrome-cookie transfer is permitted.

## Auth and storage

Snapshots and Playwright storage state use one AES-256-GCM encrypted owner-only file on a 1 GB Fly volume. A failed, partial or expired refresh leaves old evidence unavailable to MCP until a new complete refresh succeeds. Calendar TTL is 15 minutes; Messages TTL is 5 minutes.

**Fresh cloud login is separate, unimplemented work.** Practical bootstrap design: an authorized operator starts the single Machine using the personal-scoped Fly Machines API; exposes a temporary human-visible browser only through a private authenticated tunnel; completes Airbnb login and MFA *inside that cloud browser*; calls `persistFreshCloudLogin` on that same in-memory Playwright context; verifies the encrypted volume write; then removes the viewer/tunnel. No plaintext storage-state file, Mac Chrome cookie copy, challenge bypass or login was created here. Stop refresh work during bootstrap and restart afterward. Do not expose the temporary viewer publicly.

Required runtime settings: `AIRBNB_BROWSER_DATA_KEY` (32 random bytes, base64), `AIRBNB_BROWSER_CALENDAR_URLS` (JSON mapping units `1`-`3` to exact `.co.za/multicalendar/<listingId>` URLs), and **two distinct secrets**: `AIRBNB_BROWSER_MCP_TOKEN` only for `/mcp`, and `AIRBNB_BROWSER_OPERATOR_TOKEN` only for readiness, metrics, refresh and budget routes. Keep actual IDs, credentials and guest data out of Git/logs. `AIRBNB_BROWSER_MESSAGES_URL` defaults to `https://www.airbnb.co.za/hosting/messages`; `AIRBNB_BROWSER_STATE_PATH` defaults to `/data/browser-state.enc`.

## Availability and cost

`fly.toml` sets `min_machines_running = 0`, `auto_stop_machines = "stop"`, and **`auto_start_machines = true`**. Fly Proxy can wake a stopped Machine for a remote MCP call or authenticated operator refresh, making the on-demand endpoint reachable. **Fly starts it before the app checks authentication, so even an unauthenticated public request can incur startup cost.** An external scheduler, not provided here, must POST `/refresh/messages` every 5 minutes and `/refresh/calendar` every 15 minutes with the operator token. No schedule, app or volume was created.

Public `GET /healthz` is liveness only and includes a `ready` boolean. Operator-only `GET /readyz` returns 503 until auth, both complete fresh snapshots, and budget checks pass. Operator-only `/metrics` contains no guest data. MCP cannot call operator routes, and the operator token cannot call MCP.

The software gate reserves **US$7.50 per SAST month for a full-month 1 GB shared-CPU Machine** (above the approximate US$6.8 JNB quote), US$1 for one 1 GB volume, up to 4 GB stopped rootfs and snapshots, US$0.50 for the 2 GiB transfer ceiling, and US$0.25 unmetered headroom. That commits US$9.25 before model calls; **Agents API spend is capped at US$0.70/month** through operator-only `/budget/reserve-agent`, leaving US$0.05 margin. It separately tracks actual process-started seconds at US$0.01/hour and transfer at US$0.25/GiB. Runtime checkpoints run every 60 seconds and on shutdown. Browser runs cap at 50 MiB; MCP results cap at 256 KiB. The service makes zero model calls itself.

This is **not an invoice-enforced US$10 cap**. Pre-auth public wakeups, image rootfs size, live region price, extra Machines/volumes/IPs, model calls outside the reservation path, and abrupt-kill time are not independently reconciled. Verify a live JNB quote, image/rootfs and Fly bill, deploy exactly one Machine and volume without a dedicated IP, and add an account-level cap/alert before rollout. [Fly pricing](https://fly.io/docs/about/pricing/) documents running Machine, stopped rootfs and volume billing. No live go-live is authorized until real quote and usage metrics are checked.

## Agents API

Bearer-authenticated `POST /mcp` is a stateless Streamable HTTP MCP endpoint exposing only `get_calendar_snapshot`, `list_message_threads`, `get_message_snapshot`, `refresh_before_plan` and `get_pilot_status`. No arbitrary browser executor or Airbnb write tool exists; typed future actions return `READ_ONLY_PILOT`. Guest text is untrusted evidence, not instructions. `agents-adapter.mjs` builds the narrow service-origin HTTP MCP connection with `environment: {type: "none"}`, following the [official Agents API MCP guide](https://developers.openai.com/api/docs/guides/agents-api/tools/mcp) and [environment-none quickstart](https://developers.openai.com/api/docs/guides/agents-api/quickstart). Protocol tests run locally; no OpenAI session was created.

Build context is the repo root; `Dockerfile` pins the official Playwright image to the package version. Future Fly work must use only `/Users/tristdrum/.local/bin/fly-personal` after verifying personal-account identity. This branch authorizes no deployment, login, secret creation or guest communication. Run `npm --prefix apps/airbnb-browser test` for synthetic checks.
